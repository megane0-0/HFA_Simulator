# 確認手順

`index.html` を変更したときの検証手順です。ヘッドレス Chromium（Playwright）で走らせます。

`index.html` はローカルの HTTP サーバーで配信してから開いてください。localStorage を使うため `file://` では正しく検証できません。

```bash
python3 -m http.server 8000
```

実装の詳細は [CLAUDE.md](../CLAUDE.md)、緑内障プリセットの値の根拠は [緑内障プリセットの設計.md](緑内障プリセットの設計.md) にあります。

## 1. 値の確認

期待値は `index.html` 内の `GLAUCOMA_OD` から**独立に再計算**し、アプリの出力（localStorage の `hfa-sim-data-v2`）と突き合わせます。アプリ自身の関数を使って比較すると、両方が同じように壊れていても通ってしまうためです。

- プリセット7種 × 右眼・左眼で、76点すべてが期待値どおりか
- 左眼で `OS[x, y] === OD[-x, y]` が成立し、かつ右眼と同一配列になっていないか
- 既存4種（正常視野・求心性視野狭窄・中心暗点・上半視野欠損）の値が変わっていないか
- 「この眼をもう一方へコピー」が反転せず複製するか
- リロード後に76点データ・画角・表示眼が復元されるか
- `pageerror` / `console.error` が0件か
- 補間マップ（64×64）が右眼と左眼で鏡像になっているか

補間マップの鏡像性は `gridMap` を直接比較します。76点の値が合っていても補間側で向きを取り違える余地があるため、描画に使う配列まで確認します。

## 2. 疑似カメラでの撮影

標識や文字のある街の絵を用意し、Chromium の疑似カメラに入力します。文字や標識を四隅と中心に置くと、どの象限が欠けたか判断できます。

```
--use-fake-device-for-media-stream
--use-fake-ui-for-media-stream
--use-file-for-fake-video-capture=<path>/scene.y4m
```

画角は46°に設定し、次を確認します。

- **右眼のみ**: 初期・中期で画面左上（右眼の上鼻側）がぼけ、中心は明瞭。後期は上半視野がほぼ消失し、中心の小島と右下（下耳側）が残る
- **左眼のみ**: 左右が反転する
- **両眼**: 片眼だけ緑内障でもう片方が正常なら、欠損はほぼ出ない

### y4m の作り方

Playwright 同梱の ffmpeg は**PNG デコーダを持たない簡易ビルド**なので、PNG からの変換はできません。自前で書き出します。

1. canvas から `getImageData` で RGBA を取り出す
2. BT.601 で YUV420 に変換する
3. ヘッダ `YUV4MPEG2 W960 H540 F15:1 Ip A1:1 C420mpeg2` を付け、フレームごとに `FRAME\n` + Y + U + V を並べる

静止画でよいので、同じフレームを数十枚並べれば足ります。Chromium はファイルの終端に達すると先頭へ戻ります。

### 撮影時の注意点

いずれも一度つまずいた箇所です。

- **Playwright の要素スクリーンショットは canvas の更新を拾えないことがあります。** `outCanvas.toDataURL()` で直接ビットマップを取り出してください。要素スクリーンショットだと、条件を変えても同じ画像が並びます
- **入力タブへ移動するとカメラが止まります**（`switchTab` の仕様）。プリセットを変えるたびに入力タブへ行くので、**条件ごとに「カメラ開始」を押し直す**必要があります。押し直さないと `renderLoop` が動かず、画面が前の状態のまま固まります
