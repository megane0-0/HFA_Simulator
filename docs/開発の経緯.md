# 開発の経緯

このアプリが**なぜ今の作りになったのか**を残す文書です。現在の実装の説明ではありません。

- **仕様の正**は [README.md](../README.md) と `index.html` です
- **現在の実装と設計の要点**は [CLAUDE.md](../CLAUDE.md) にあります（`levelForDb` の境界、IDW補間の設計、レベル別フィルターのパラメータ、緑内障プリセットの表の持ち方、変更時の確認手順）
- この文書は、そこに至るまでに何を試して何をやめたかを書きます。同じ検討を繰り返さないための記録です

README の「iOS版からの主な変更点」は**何が変わったか**の一覧です。この文書はその**理由**を扱います。

## 出発点：iOS版と当初の要件定義（2025年）

iPhoneアプリとして企画したのが始まりです。目的は「言葉では伝えにくい見え方を、家族や支援者と共有すること」。対象は患者本人・家族・支援者で、医療機器ではないという位置づけは当初から変わっていません。

当初の要件定義は手元の非公開資料にあり、iOS前提で書かれています。現在のWeb版とは何か所も食い違うため、**設計判断の根拠として参照しないでください**。主な食い違いは次のとおりです。

| 項目 | 当初の要件定義 | 現在 |
|---|---|---|
| プラットフォーム | iOS（Swift/SwiftUI） | 単一HTML |
| OCR取り込み | 中心的な機能として記載 | 未実装（後述） |
| グリッドサイズ | 64×64 と 512×512 が混在（512×512は誤記） | 64×64 |
| 補間アルゴリズム | 「双線形補間」と記載 | IDW（実装当初から） |
| dB の区切り | 25 / 20 / 15 / 10 | 25 / 15 / 5 / 1 |
| 暗点の表現 | 減光・黒塗りを含む | ぼかしのみ（後述） |
| データの保存先 | 端末内ストレージ | localStorage |

こうした食い違いがあるため、**仕様の正は README と index.html、経緯はこの文書**という整理にしています。iOS版の最終形（Swift）はこのリポジトリの外に保管しています。

## フィルターを作り直した（2025年・iOS版の時期）

初期のiOS実装は、レベル1〜4のすべてにレベル2のブラーを流用し、マスクの濃淡でブレンドの比率だけを変えていました。

この作りだと、**ぼけ方が一定のまま「段階的に暗くなるだけ」に見えます**。背景の色を変えてもぼけ方が変わらず、欠損の重さが伝わりませんでした。

そこでレベルごとに専用のマスクを作り、レベル別の強度で作った画像を重ねる方式に変えました。これが現行の実装です（パラメータは CLAUDE.md 参照）。

## 点ではなく面で塗る（2025年・iOS版の時期 → Web版）

76点の測定点に直接フィルターを当てると、点と点の間で**境界が不連続**になりました。そのため、いったんグリッドに補間してセル単位で塗る方式へ移しています（iOS版 32×32 → Web版 64×64）。

面で塗るようにしても、暗点の内部が「測定点の真上だけ暗いまだら」になる問題が残りました。遠方の正常点に引っ張られるのが原因で、近傍4点限定のIDWと仮想中心点で解消しています（CLAUDE.md 参照）。

## 暗点を黒で塗らない方針（2026年7月に徹底）

「暗化は使わず、ぼやけで表現する」方針は当初からありましたが、実装にはレベル3の減光（35%）とレベル4の黒塗りが残っていました。

2026年7月に、**白い背景で黒が目立ちすぎる**こともあって廃止し、粗いピクセル化と強いブラーで周囲の色ににじませる表現に統一しました。UIの「真っ暗」という表記も「視認不能」に変えています。

暗点は本人には「黒く見える」のではなく、周囲に溶け込んで知覚されない状態です。黒で塗ると、その点だけ**見えている情報が増えてしまう**ため、説明の道具としては不正確になります。

## OCR取り込みの構想と断念（2026年7月）

当初の要件定義では、検査結果をカメラで撮ってOCRで読み取ることが中心的な機能でした（iOSのVision framework）。

Web版では2026年7月にTesseract.jsで実装し、読み取った数値を最近傍で測定点に割り当てる方式にしました。合成した画像では往復一致しましたが、**実際の検査結果の画像では精度が確保できず**、公開前に機能ごと削除しています。結果として、外部依存のない単一HTMLに戻りました。

復活させる場合は、合成画像ではなく**実際の検査結果の画像での精度検証から**始めてください。当時の課題は次の2点です。

- 24-2の54点と30-2の76点の対応づけ
- 「<0」の誤読

## 入力まわりの追加（2026年7月）

Web版への移植にあわせて、臨床で使える形に寄せました。

- **左右眼を別々に入力**（保存形式 v2、旧形式からは自動移行）。片眼だけの欠損を示せるようにするため
- **dB値の直接入力**。検査結果の数値をそのまま入れられるように
- **カメラ画面での表示眼の切替**（右眼／左眼／両眼＝better eye）
- **リセットを「この眼」「両眼」に分け、「この眼をもう一方へコピー」を追加**

## 公開と運用の変遷

2026年7月にMITライセンスでGitHub Pagesに公開しました。当初はブラウザからファイルをアップロードする運用で、この方法だとアップロード時にGitHubの添付リンクがREADMEの冒頭へ紛れ込むことがありました。

2026年9月から、Claudeが `claude/` ブランチにpushしてPRを作り、所有者がマージする運用にしています（CLAUDE.md の運用ルール参照）。`main` が公開ページに直結しているためです。
