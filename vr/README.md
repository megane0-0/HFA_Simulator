# HFA 視野シミュレータ VR版（FOVE / HTC Vive）

ハンフリー 30-2 の結果から、視線に追従する視野欠損を 360度映像に重ねて体験する Unity 用プログラムです。Web版（`index.html`）と同じ76点・同じ補間・同じレベル分けを使い、VR の中で視野データの入力もできます。

**医療機器ではありません。** 理解促進・教育目的のツールで、診断・治療の根拠には使えません。表示は視線を固定した瞬間の見え方の再現で、実際の日常は眼球運動による代償でこれより良いことが多い点も、体験者に伝えてください。

## 構成

`HfaVr` フォルダを Unity プロジェクトの `Assets` にコピーして使います。共通部分は1つで、機種ごとの入口が2つあります。

| ファイル | 役割 |
|---|---|
| `Scripts/HfaVrFove.cs` | **FOVE 用の入口** |
| `Scripts/HfaVrVive.cs` | **HTC Vive 用の入口** |
| `Scripts/HfaVrApp.cs` | 本体（表示・操作・保存） |
| `Scripts/HfaField.cs` | 76点・プリセット・補間（Web版からの移植） |
| `Scripts/HfaGaze*.cs` | 視線の取得（FOVE / OpenXR / SRanipal / 頭の向き / マウス） |
| `Scripts/HfaPanel.cs` | VR 内の入力パネル |
| `Scripts/HfaMedia.cs` | 360度の写真・動画の読み込み |
| `Resources/HfaGazeSphere.shader` | 360度映像に視線追従の欠損を重ねるシェーダー |

FOVE のプラグインと OpenXR は同じプロジェクトに入れると干渉しやすいので、**機種ごとに別の Unity プロジェクト**を作ることを勧めます。レンダーパイプラインは Built-in を想定しています。

## セットアップ: FOVE（FOVE0 / FOVE480）

1. Unity 2021.3 LTS で 3D（Built-in）プロジェクトを作る（このプログラムは Unity 2019.4 以降が必要。コンパイル確認は 2021.3。FOVE Unity Plugin v4.5 は Unity 2018.4 以降・FOVE ランタイム v1.4 以降に対応）
2. FOVE Unity Plugin（https://github.com/FoveHMD/UnityPlugin ）をインポートする
3. `HfaVr` フォルダを `Assets` にコピーする
4. Player Settings の Scripting Define Symbols に `HFA_FOVE` を追加する
5. シーンのカメラを FOVE のプレハブ（Fove Interface または Fove Rig）に置き換え、タグを `MainCamera` にする
6. 空の GameObject を作り、`HfaVrFove` を付ける
7. FOVE ランタイムを起動して再生する。視線の較正は F1 キー

FOVE480 は位置トラッキングがなく、頭の回転のみです。360度映像は無限遠にあるものとして描くので、このプログラムでは支障ありません。480Hz の視線追跡は CPU 負荷が高く、USB ハブ経由の接続は避けるよう公式に案内されています。

## セットアップ: HTC Vive

1. Unity 2021.3 LTS 以降で 3D（Built-in）プロジェクトを作る
2. XR Plug-in Management で OpenXR を有効にし、OpenXR の設定で **Eye Gaze Interaction Profile** と **HTC Vive Controller Profile** を追加する
3. Player Settings の Active Input Handling を **Both** にする
4. `HfaVr` フォルダを `Assets` にコピーする
5. カメラに Tracked Pose Driver を付け（または XR Origin を使い）、タグを `MainCamera` にする
6. 空の GameObject を作り、`HfaVrVive` を付ける
7. SteamVR（または VIVE のランタイム）を OpenXR ランタイムに設定して再生する

VIVE Pro Eye で OpenXR から視線が取れない場合は、SRanipal SDK の Unity パッケージを入れ、Scripting Define Symbols に `HFA_SRANIPAL` を追加してください。SRanipal 経由に切り替わります。

Vive 側の手順と API は、公式ドキュメントを開けない環境で書いたため記憶に基づいています。メニュー名やプロファイル名が違う場合は、実際の画面に合わせてください。

## 360度映像

`Assets/StreamingAssets/360/` に、正距円筒図法（横:縦 = 2:1）のモノラルの写真（jpg / png）や動画（mp4 など）を置きます。名前順に N キーで切り替わります。何も置かなければ、確認用の模様（10度ごとの格子と色の柱）が出ます。

- 写真は横 4096〜8192px を勧めます。解像度が低いと、欠損のない部分もぼけて見えます
- 上下に分かれたステレオ（3D）の360度映像には対応していません
- 患者さんが写っている映像を使う場合は、院内の取り決めに従ってください

## 操作

体験者がヘッドセットをかぶり、操作者が PC のキーボードで操作する想定です。Vive ではコントローラーでも塗れます。

| キー | 動作 |
|---|---|
| M（Vive: メニューボタン） | 入力パネルを開く・閉じる |
| E | 表示する眼の切替（左右それぞれ → 右眼のみ → 左眼のみ → 両眼の良い方） |
| O | 視野30度より外の扱い（外周の値を延長 → 黒 → 加工しない） |
| N | 次の映像　／　`[` `]` 映像を15度ずつ回す |
| G | 視線の取得元（視線追跡 → 頭の向き → マウス） |
| V | 視線の位置に印を出す（較正の確認用） |
| X | 欠損表示のあり／なし（元の映像との見比べ） |
| F1 | 視線の較正 |
| F2 | 左右確認（左の画面を赤、右の画面を青に着色） |

入力パネルを開いているとき:

| キー | 動作 |
|---|---|
| 点を見る＋Space（Vive: トリガー） | その点を今のレベルで塗る。押したまま視線を動かすと連続で塗れる |
| 0〜4（Vive: パッド上下） | 塗るレベル（30 / 20 / 10 / 3 / 0 dB） |
| ↑ ↓ | 見ている点を ±1 dB（Shift で ±5 dB） |
| Tab | 入力する眼（右眼 / 左眼） |
| P（Shift+P で戻る） | プリセットを選ぶ |
| Enter ／ Shift+Enter | この眼に適用 ／ 両眼に適用 |
| C | この眼をもう一方へコピー（反転なし） |
| R ／ Shift+R | この眼をリセット ／ 両眼をリセット |

パネルは Web版と同じく、患者から見た向き（右眼なら左が鼻側）です。緑内障を両眼に入れるときは、コピーではなく Shift+Enter を使ってください（左眼で左右反転します）。同名半盲は反転しません。

## データの保存と Web版との関係

視野データは `Application.persistentDataPath` の `hfa-sim-data-v2.json` に保存されます（Windows では `C:\Users\<ユーザー名>\AppData\LocalLow\<会社名>\<プロダクト名>\`）。起動時に画面にも場所が出ます。外部送信はありません。

中身は Web版の localStorage（キー `hfa-sim-data-v2`）と同じ `{"od":[76個],"os":[76個]}` です。Web版にはまだ書き出し・読み込みのボタンがないため、現時点では手作業でのコピーになります。

## Web版との違い

- **視線追従**: 欠損が視線の位置についてきます。Web版は画面中心に固定です
- **左右の眼を別々に表示できる**: 既定の「左右それぞれ」では、左の画面に左眼、右の画面に右眼のデータを使います。両眼視での見え方は体験者自身の融像に任せる形で、Web版の「各点で良い方を採用」とは別のモデルです。どちらが実際の両眼視に近いかは検証していません
- **ぼかしの作り方**: Web版はレベルごとにピクセル化とブラーをかけた層を重ねます。VR版は映像のミップマップ（縮小画像）を多点で読んでぼかします。レベルの境界（25 / 15 / 5 / 0 dB）は同じですが、境界の前後 1 dB をなめらかにつないでいます。ぼかし幅は視角で 0.5 / 1 / 2.5 / 5 度（Web版の画角46度相当）を既定にしており、Inspector の `Blur Deg` で変えられます。見た目が Web版と同等かは実機で要確認です
- **視野30度より外**: Web版は黒ですが、VR では視界の大半が30度より外になり、黒にすると正常視野でも強い求心性狭窄に見えます。そのため既定は「外周の値を延長」にしました。測定していない範囲を推定で埋めていることになるので、説明の場面に合わせて O キーで切り替えてください
- **減光・黒塗りを使わない方針**は Web版と同じです

## 初回の確認

1. **エディタで再生（ヘッドセットなし）**: 模様が見え、マウスの位置を中心に欠損が動くか。右ドラッグで見回せます。Console にシェーダーのエラーが出ていないか
2. **M でパネル**: 76点が Web版と同じ並びで出るか。P → Shift+Enter で緑内障中期を入れ、右眼の左上が暗い色になるか
3. **ヘッドセットで F2**: 左眼に赤、右眼に青が見えるか。逆や単色なら左右の判定が効いていないので、E キーで「右眼のみ」「左眼のみ」を使ってください（その場合は連絡をください）
4. **V で視線の印**: 見ている場所に黄色い輪がついてくるか。ずれるなら F1 で較正
5. **緑内障中期を両眼に入れて E で切替**: 右眼のみで左上、左眼のみで右上がぼけるか
6. **頭を動かしたとき**に、映像と欠損がぶれたり遅れたりしないか

## 既知の制限

- 視線追跡の遅れとぼかしの境界のちらつきは `Gaze Smoothing`（既定0.02秒）で調整します。大きくすると安定しますが、欠損が視線に遅れます
- まばたきなどで視線が取れないフレームは、直前の向きを保ちます
- 天頂・天底付近では、ぼかしが横に伸びます（正距円筒図法の性質）
- 中心窩 dB の入力と 24-2 への切替（Web版の PR #8）には未対応です
- 両眼の視線は1本（両眼を合わせた向き）として扱っています。斜視のある体験者では、眼ごとの欠損位置がずれます
